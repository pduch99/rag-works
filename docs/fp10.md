# FP10: fixing the evidence, the framework, and a complete run

## Goal

FP7 showed that better retrieval made answers worse: retrieval pass went from 0.77 to 0.92 while answer score dropped. FP10 set out to find out why, fix it, finish a complete run of every step, and turn the project into the framework the original scope asked for.

## What was built

**Complete runs on a local model.** Groq's free daily limit cut every earlier run short. FP10 added Ollama as a third provider. A local vision model (`qwen3-vl:8b-instruct`, context raised to 12288) runs on an RTX 3060, so a full five-step evaluation finishes in about 15 minutes with no rate limits. Two setup problems came up and were fixed: the default "thinking" model spent its token budget before answering, and Ollama's 4096-token default rejected every request with images.

**Five evidence fixes, each found by reading the traces of failed answers:**

| problem seen in a trace | fix |
|---|---|
| the model said the parking ramp was north of the Student Center using `PARKING RAMP AND LOT (59,23)`. That is the map legend, not the ramp | find the legend box from its heading and drop labels inside it |
| the Student Center label (y=44) sat on the seam between two image crops | split figures with 15% overlap, so the Student Center and the ramp are both in the NE and SE crops |
| image descriptions gave positions inside the crop (`STUDENT CENTER | 30,88`), label lists gave positions on the page | convert description positions to page positions (`65,44`) and mark legend entries |
| a calendar date and its event could end up in different chunks, and dates were mistaken for headings | each date line plus its event becomes one record. Records get 500-character chunks |
| the grader and judge read 700-800 characters of evidence while the answer model read 1500, so correct answers were marked unsupported | every stage reads the same 1500 characters, and the judge also sees label positions and spatial facts |

**Fixes for a weaker checker.** The 8B grader threw away the right crop. It can no longer drop the top hit or the top image, and it only re-searches when nothing at all was relevant.

**Spatial facts (new RAG technique, the fp10 step).** Even with correct evidence, the 8B model misread its own numbers ("the ramp is at (53,55)" when the evidence said 80,56) and flipped directions. The new `rag/spatial.py` finds the places a question names among the page's labels and writes the directions in code: `PARKING RAMP (80,56) is south-east of STUDENT CENTER (SC) (68,44)`, plus the nearest landmarks around each place. It costs under 1 ms and no model calls.

**Faster.** The reranker now reads at most 10 candidates. Our own code per question dropped from about 470 ms to about 260 ms (median). Everything except the reranker and the question embedding takes under 5 ms.

**The framework.** A new framework tab and `docs/framework.md` (both from `rag/framework.py`):
- RAG as seven stages
- a catalog of 13 RAG types in five groups, each described with the same fields
- a "try" button that sets the app's switches to that type
- the measured before and after for each implemented type
- a chart of the full FP6-FP10 run

**Shareable.** README rewritten around the framework, `setup.bat` / `setup.sh` / `run.bat` / `run.sh`, a paste-your-key box for people without a `.env`, `.env.example` covering all three providers, and a `.gitignore` that keeps `.env` out.

## Results

All 14 Metro State gold questions, local `qwen3-vl:8b-instruct` for answering and judging, Nov 17 2026. Each step changes one stage from the one before.

| | fp6 baseline | fp7 better index | fp8 hybrid + rerank | fp9 labels + self-check | fp10 spatial facts |
|---|---|---|---|---|---|
| retrieval pass | 0.77 | 0.92 | 0.92 | 0.92 | 0.92 |
| recall@5 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| mrr | 0.72 | 0.81 | 0.84 | 0.84 | 0.84 |
| answer score | 0.68 | 0.57 | 0.54 | 0.61 | **0.64** |
| grounded | 0.93 | 0.71 | 0.71 | 0.86 | **0.93** |
| key facts | 0.59 | 0.51 | 0.56 | 0.56 | **0.63** |
| hallucinated | 0 | 0 | 0 | 0 | 0 |
| model calls / question | 2.0 | 2.0 | 2.0 | 3.6 | 3.5 |
| our code ms / question | 325 | 56 | 309 | 282 | 262 |

Before the evidence fixes, the first four steps scored 0.68 / 0.54 / 0.57 / 0.43 on answers (fp6-fp9). The fp6 column was identical question by question across runs, so the evaluation repeats.

## What the results say

1. **The bottleneck moved at each stage.** FP2-FP6 were limited by retrieval. Once retrieval passed (0.92), the limit was the evidence the model received: legend labels, crop seams, mixed coordinate frames. Once the evidence was right, the limit was the model's own reasoning. The framework is what made each move visible: every answer is diagnosed as a retrieval or a generation failure.
2. **Better retrieval made answers worse, on two different models.** Groq's 27B model (FP7: 0.64 → 0.46) and the local 8B model (0.68 → 0.57) both dropped. Fixing the evidence, not the search, brought answers back to 0.64 and grounding back to 0.93.
3. **Code beats a small model at geometry.** Spatial facts fixed map-04 (St. John's Hall, west of the Student Center).
4. **A small model can contradict a fact it was handed.** On map-03 it was given `PARKING RAMP is south-east of STUDENT CENTER` and answered "north-east… which implies the parking ramp is to the north-east". Its own verifier, the same model, marked that claim OK. Self-checking only helps when the checker is stronger than the model it checks.
5. **No hallucinations in any step.** The unanswerable question was refused correctly every time.

## Known failures

- **txt-03** ("When does fall 2026 registration begin?"): the calendar has "Fall 2026 registration begins in eServices" (March 23) and "Fall 2026 OPEN (visiting students) registration begins in eServices" (June 8). Search picks June 8. Two nearly identical facts. Sending one more text chunk would likely fix it; it was left as a known limit when features were frozen.
- **map-03** on the 8B model, as above.
- **Vague answers** ("TUNNEL, SKYWAY") get partial credit on map-07 and map-08. The facts are right but the answer is thin.

## Limits of the evaluation

- 14 questions, one map, four web pages. The evidence fixes were found by studying this map, so a wider test set is needed to show they generalize.
- On local runs the judge is the same model that answered. Judge grades should be spot-checked by hand (the evals tab has a `checked` column for this).
- The four new crop descriptions in fp7-fp10 were written by the local model; older ones came from Groq. FP6 is unchanged.

## Next
